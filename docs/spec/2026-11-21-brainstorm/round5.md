## 1. 事实修正：AI 能力的平台事实（长期有效，后续不得基于旧事实提案）

**平台事实（需求方核实）**：

- Intents Kit 可以当作不存在；
- 小艺 Agent 在 2in1 上不可用；
- AI 问答功能**只能 BYOK**（用户自带 API Key）；
- **【2026-11-22 补记（已确认）】**「ArkTS Skill 机制接入小艺 Work」为**不同机制**：小艺 Work 是本地运行的 harness，可经 Skill 连接鸿蒙应用，且 harness 本身可执行命令行。系统级 AI 操控路径据此以新功能点复活（`decisions.md` 第 32 条），并确立架构定位——BrewLibrary 作为 Agent 可调用的技能层（口径 / 适配事实 / 护栏状态），而非与 Agent 竞争执行。

**对既有条目的影响**：round1 D1 / D2 / D3（AI 讲解包 / 自然语言找包 / AI 报错诊断）的
实现路径为 **BYOK + 确定性降级**：

- BYOK：开发者用户本就持有 API Key（与「核心用户是开发者」的画像自洽，甚至比通用
  App 更顺）；Key 存系统安全存储；按 token 缓存的 TTL 设计不变（省 Key 费用反而成为
  BYOK 模式下的正当理由）；
- 确定性降级：AI 不在线 / 未配 Key 时，D1 落到 tldr 示例（round2 I）与结构化详情本身，
  D2 落到中文任务词表（round2 微项）——**AI 是增强层不是依赖层**，与「离线可搜」的
  降级哲学同构。

## 2. W′ · 工具清单同步（收窄版）

**一句话**：只同步**主动安装（install-on-request）的库**及其 taps——「换机时，一键复制
你的旧电脑 CLI 环境」「台式机 + 笔记本双机互见」。

- **收窄依据（需求方裁定）**：全量 Brewfile 太庞大且无意义——依赖包不该同步（装 A
  自然带 B），主动清单才是「我的工具链」；口径与 Discover 的 install-on-request、
  「我的」页「隐藏作为依赖安装的包」chip 完全同源，与 Brewfile 语义（`brew bundle dump`
  只 dump 主动安装）天然一致。
- **体积**：KB 级（几百 token + taps 行），同步成本可忽略。
- **两个交互**：
  1. **换机**：新机上打开同步清单 → 逐条标注适配态（A）→ 勾选进批量安装队列（B′ 的
     队列）；这就是「一键复制 CLI 环境」。
  2. **双机互见**：台式机打开 App 时一张轻量卡「你的笔记本今天新装了 gh、jq」→ 一键
     跟装。把「发现好库」在自己两台机器之间流转（与 round2 C1 新适配速递同一心理模型）。
- **机制分级**：v0 = 文件流（导出到 `Download/<bundleName>/`，经任何渠道自传，零云依赖）；
  v1 = 账号端云同步（默认关、显式开启；「数据离开设备」的隐私叙事变化需明确的用户协议）。
- **与 B′ 的关系**：W′ 就是 B′ 导出链路的同步化增强，不新增页面骨架。
