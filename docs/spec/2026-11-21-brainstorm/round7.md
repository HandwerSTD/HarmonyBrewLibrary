## 1. AB · 全生态安装指令翻译器

**一句话**：用户粘贴一条其他 Linux / macOS 包管理器的安装命令，甚至一段教程，BrewLibrary
将其转换为经过本地目录校验的 HarmonyOS 软件包候选与安装计划。

例如：

```bash
sudo apt update
sudo apt install git fd-find ripgrep
```

转换结果：

- `git` → Homebrew `git`；
- `fd-find` → Homebrew `fd`；
- `ripgrep` → Homebrew `ripgrep`；
- `apt update` 不是软件安装请求，不纳入安装队列；
- 安装后提供的典型命令包括 `fd`、`rg`。

最终结果进入既有安装预演与批量安装流程，不直接执行用户粘贴的命令。

## 2. 与 AI 搜索的关系：同一底座，不同输入

| 能力 | 用户输入 | 要解决的问题 | 输出 |
|---|---|---|---|
| D2 AI 自然语言找包 | 「我想快速搜索代码，该装什么？」 | 从模糊意图发现工具 | 经目录校验的候选包与解释 |
| AB 安装指令翻译 | 「教程让我执行 `apt install fd-find`」 | 把明确的外部安装材料映射到本机生态 | 经目录校验的候选包、映射说明与安装计划 |

两者共享同一条核心链路：

> **理解语义 → 建立跨平台包名映射 → 用本地目录与当前软件源验证 → 给出候选包。**

AB 的增量不是另造一套搜索，而是：

1. 识别 apt、dnf、pacman、yum、brew 等命令方言；
2. 从整段教程中批量提取安装步骤并去重；
3. 处理跨生态包名、命令名和别名差异；
4. 将结构化结果接入安装预演与批量安装队列。

因此在产品入口上，它更适合作为 AI Companion 的「粘贴教程 / 命令找包」模式，与文字提问等
输入方式并列，而不是新增一个独立产品中心。

## 3. 真实用户价值

HarmonyOS PC 用户仍需大量参考 macOS、Ubuntu、Debian、Arch 等平台的教程。用户需要自行判断：

- 教程使用了哪种包管理器；
- 包名在 Homebrew 中是否相同；
- 当前 HarmonyOS 软件源是否收录；
- `fd-find` / `fd` 等名称差异是否指向同一工具；
- 安装后的命令名是否发生变化；
- 没有同名包时是否存在有证据的替代工具。

AB 将这类重复查找压缩为一次粘贴和一次确认，但仍停留在应用市场的「发现—校验—安装」主线内，
不扩张为项目环境管理或通用 Shell 翻译执行器。

---

## 4. 完整处理流程

1. **输入**：用户主动粘贴命令或教程片段，也可通过既有分享入口送入；
2. **提取**：识别安装命令、包名、选项与注释，忽略非安装步骤；
3. **方言解析**：处理不同包管理器的语法及 `sudo` 等包装，不把平台专用参数机械带入 brew；
4. **身份映射**：结合跨生态映射表、包元数据、命令名与别名关系生成候选；
5. **事实校验**：候选必须命中本地目录，并标注当前软件源中的可用状态；
6. **结果分级**：
   - 直接映射；
   - 名称不同但已找到对应包；
   - 没有同名包但存在有证据的替代工具；
   - 无法确认，需要用户判断；
7. **安装闭环**：用户勾选候选后进入既有安装预演，确认后才进入安装队列。

## 5. 决赛展示方式

从一篇 Ubuntu 教程中复制混合命令并粘贴：

```bash
sudo apt update
sudo apt install git fd-find ripgrep
```

BrewLibrary 展示：

> 已识别 Ubuntu 安装命令；已转换为 HarmonyOS 安装方案：`git`、`fd`、`ripgrep`。
> `apt update` 不属于软件安装，未纳入队列。

随后展示每个映射的依据，并进入安装预演。展示重点不是「AI 改写了一行字符串」，而是
**真实教程材料经过结构化解析和本地事实校验，直接变成可审查的安装计划**。

## 6. 实现体量与 AI 边界

### 6.1 真正需要建设的部分

- 多包管理器安装命令解析器；
- 跨生态软件身份、包名、命令名与别名映射数据；
- 本地目录和双源可用性校验；
- 教程片段的批量提取、去重与冲突处理；
- 结构化结果到安装预演 / 批量队列的接口。

主要成本在映射数据和事实校验，不在输入框或 AI 文案。

### 6.2 AI 与确定性降级

- 已知命令方言与已知映射优先使用确定性规则；
- AI 用于理解不规则教程上下文、识别候选映射和生成解释；
- AI 给出的包名必须经过本地目录过滤，不能凭模型记忆直接安装；
- 无 Key、断网或模型不可用时，已覆盖的命令与映射仍可使用；
- 无法确认时明确显示「无法确认」，不得把替代猜测写成事实。

### 6.3 执行边界

- 只翻译软件安装意图，不承诺翻译教程里的任意 Shell、构建或服务配置命令；
- 不直接执行用户粘贴的原始命令，也不静默执行 AI 生成命令；
- 安装前仍沿用既有预演、命令展示和用户确认；
- 「替代工具」必须限定场景，不能宣称与原创程包完全等价。

## 8. 留存结论

| 条目 | 定位 | 建议强度 | 主要成本 |
|---|---|---|---|
| AB · 安装指令翻译 | AI Companion 的「教程 / 命令找包」增强，不单独作为主功能叙事 | ★★★ | 跨生态映射数据与方言解析 |
