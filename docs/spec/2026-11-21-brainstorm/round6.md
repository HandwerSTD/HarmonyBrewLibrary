## 3. B′ · 开局与多机工作台（B 的重构）

**认知转变**：迁移是「把旧世界搬过来」——一次性事件，前提已死；**开局是「把这台新电脑武装到能干活」——每一台新机器都会发生**，随鸿蒙 PC 出货重复出现。开局的市场比迁移大，且不依赖任何「换平台」故事：鸿蒙 PC 新用户从零配环境是普遍事件，团队 Brewfile（新人复现环境）在任何组织都存在。

三条输入路径，共用同一条「适配标注（A）→ 勾选 → 批量安装队列（落盘持久化）」管线：

| 路径 | 场景 | 数据来源 |
|---|---|---|
| ① 策展开局套装 | 新机器从零配环境：「前端开局」「服务端开局」「AI 工具开局」…… | 策展 + 真实下载量排序（C4 供数）+ A 标注 |
| ② Brewfile 导入 | 团队标准化 / 同事分享 / 自己的另一台机器 | 纯文本解析（round1 B 既有能力） |
| ③ 远程主机直连 | 服务器 / 第二台 PC /（展望）旧 Mac | round5 X 的 SSH 通道 |

## 4. X 的重锚与降级

> **2026-11-22 二次裁定（同日，需求方追问）**：重锚不成立——三个锚点重压后均不足以
> 支撑「中-高成本」的立项。X 整体**搁置，随 Mac 迁移同入展望**（见 round5 §3 裁定注）。
> 本节以下原文保留作为重算存档。

- 场景一（旧 Mac 直连）降级为**附带可能**：并存 ≠ 迁移——用户可能仍拥有一台 Mac，连上就读，有则用之，不作为叙事前提。
- **主锚点**：Linuxbrew 服务器 / NAS——服务器不会「迁移走」，远程管理是持续需求；**次锚点**：第二台鸿蒙 PC（W′ 的 live 版）。
- 强度 ★★★★★ → ★★★★；成本中-高；「探针先行」结论不变（ssh 二进制探针 → libssh spike）。
