# BrewLibrary · Motivation

> 2026-11-22 v3。路演主线叙事：场景开场 → 四个想法 → 功能点为证 → 边界与收束。
> 背景事实与数字口径见 `relatedwork.md`（前期调研）；功能点裁决见 `decisions.md`，否决记录见 `rejected.md`。

---

## 开场：几个真实的场景

一个陌生人：他买了鸿蒙 PC，想在电脑上处理视频，在华为开发者论坛发帖问——「鸿蒙电脑里有没有类似应用商店的简单方法，搞个 ffmpeg 命令行用？」他要的从来不是 Homebrew，是一个看得懂的 ffmpeg。

然后是我自己（作者）的几个日常：

- **想做一件事，不知道有什么工具。** 想给视频抽帧、想批量重命名图片、想抓个包——每一样都隐约觉得「命令行世界肯定有现成的」，但叫什么、哪个是主流、哪个已经弃坑，全不知道。搜到的博客一半过时，剩下的一半在推销。
- **工具装上了，我却看不懂它。** 装完时终端滚过几行英文警告，说了什么、要不要照做，没人告诉我；跑起来报错，更是一屏天书。
- **不敢按回车。** `brew upgrade` 之前我总会犹豫：这些直接操作底层的软件，谁保证这次更新不把环境搞坏？卸载更是想都不敢想——万一别的工具靠它活着呢。
- **平时懒得管。** 装了什么、哪些过期了，平时完全不 care；直到磁盘告急才想起来 autoremove——而那时已经说不清这几十 GB 是谁吃掉的。
- **两台机器，两个世界。** 今天在笔记本上发现一个好工具，回到台式机想装，又得从头搜一遍、从头装一遍。

这些场景背后站着同一个人群：**轻度开发者、刚入行的开发者、刚把类 Unix 当主力机的用户**——会用终端，但没有生态知识与 SOP。16,356 个包的世界对他们敞开着，却看不懂、不敢动、带不走。资深运维不在此列，他们的清单长在自己身上。

BrewLibrary 是四个想法的回答。

## 主线一 · 选型信任 ——「像挑选软件一样挑选 CLI」

**想法**：老手和新手的差距，是一张看不见的清单——什么任务有什么工具、哪个是当下主流、哪个已经弃坑。应用商店用评分、评论、榜单把 GUI 世界的这张清单产品化了；命令行世界的选型，至今靠搜索引擎的运气和博客的施舍。把老手十年的直觉做成产品，新人就不再需要熬十年。

**功能点**：

- 已建成：16,356 个包的全量目录、16 分类、离线全文搜索；**六张榜单由真实下载量在设备端现算**——没有编辑推荐位，什么热、涨多快，都是真数据；
- 本期规划：趋势线（「它还活着吗」一眼可见）、新适配速递（本周新进了什么）、AI 编程工具策展榜（当下最热的一批，真实下载量排名）。

---

## 主线二 · AI Companion ——「终端旁随叫随到的老手」

**想法**：问老手一次的成本很低，难的是老手要随叫随到、不嫌你蠢、还不会瞎说。师徒制正在消失——远程办公见不到人、社区里问蠢问题会被甩一句 RTFM——于是新人的真实策略是瞎猜硬扛。AI Companion 把「问老手」装进应用。

**功能点**：

- **问包**：这个工具是干嘛的、适不适合我、装完怎么用——中文讲人话；
- **问需求**：「我想批量压缩图片」→ 直接找到工具，不用先知道它叫什么；
- **问报错**：安装或运行失败，stderr 翻译成人话，告诉你哪里错了、怎么修；
- **示例即抄即用**：tldr 社区的真实用法示例（中文现成），每条可复制、可一键执行；
- **系统级**：对小艺说「装个 ffmpeg」——小艺 Work 经 Skill 调用 BrewLibrary 完成查询与安装，预演确认后执行。**AI 发起，人类点头。**

**怎么做的（三句话）**：AI 只基于包的元数据和 tldr 人工审校内容回答，不编造；没配 Key、断网时，搜索与示例照常可用（AI 是增强层，不是依赖层）；用你自己的 API Key，存在系统安全存储里。

## 主线三 · 装完之后，有人管 ——「命令行不缺力量，缺护栏」

**想法**：GUI 世界的软件生来被照顾——更新推送、存储管家、卸载确认、回收站；命令行软件装完即荒野。brew 从不主动说一句话（实测），更新靠想起来，旧版本悄悄吃磁盘，卸载靠胆量。「怕」和「懒得管」不是用户的缺点，是这个世界缺失照顾体系的证据——**该补上的是产品，不是要求用户变成运维**。

**功能点（两拍）**：

- **动手时刻**：装机预演（按回车前摊开将装什么、占多少、改什么）→ 卸载安全网（卸载前告诉你谁会坏）→ 版本回滚（升级翻车一键回退）→ 装后待办（brew 告诉你的三件必做的事，变成持久清单，而不是滚走的文本）；
- **平时**：更新哨兵（有新版本，通知和桌面卡片会说一声，决定权在你）→ 磁盘管家（空间告急时，Treemap 大图指出谁吃了 40 GB，逐条勾选、安全回收）→ 体检（可选）。

---

## 主线四 · 工具链跟着人走 —— 跨设备软件包同步

**想法**：工具链是开发者最值钱又最看不见的资产，换一台机器即清零。照片、通讯录、密码早就云同步了，开发环境还在靠手工重装和记忆。这个痛大到自己长出了文化：GitHub 上数百万 dotfiles 仓库和 setup 脚本，就是专家们在徒手解决它——**专家把新电脑写成脚本，新手只能凭记忆重装**。

**功能点（鸿蒙多设备能力承载）**：

- Brewfile 导入：导入 → 逐条标注适配态 → 勾选批量安装——「换机时，一键复制旧电脑的 CLI 环境」；
- 工具清单同步：只同步主动安装的库，**双机互见**——「你的笔记本今天新装了 gh、jq」，台式机一键跟装。

## 边界

不管 GUI 应用（那是 AppGallery 的领地）；不造包（适配与否，决定权在 Harmonybrew，App 是镜子不是引擎）；不做静默升级（AI 发起，人类点头）；资深运维不是目标用户。

---

## 收束

**命令行软件占软件世界的另一半，却从未拥有过自己的应用商店语言。BrewLibrary 让它被看懂（选型信任）、被解答（AI Companion）、被照顾（装完之后有人管）、被带走（工具链跟着人走）。** 而且桥上已经通车——v1.4 里，目录、搜索、榜单与本机包管理全部真机可用。
