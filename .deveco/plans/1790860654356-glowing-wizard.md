# 移除内置 brew 数据快照

## Goal

删光应用内置的 brew 数据快照及其读取链路，让数据**只**来自设备端目录（聚合端点）+ 现网单条：

1. 删除 `common/src/main/resources/rawfile/mockdata/` 下仅剩的 4 个 brew JSON（~44 KB，目录随之为空）。
2. 删除整条 Mock 请求链路：`TriggerEnums`（仅剩 4 个 brew 成员 → 枚举整个删除）、`MockRequest`/`HmosRequest`（唯一调用方是 BrewService）。
3. Discover：六张榜骨架改为**代码构造**（不再读快照）；成员唯一来源 = 设备端目录；目录拿不到 → 空态（与 Formulae/Casks 的 C 档行为一致）。
4. Mine：三块本机包区块**空态保壳**（用户已确认）——UI 结构保留，显示 0 个包/空列表。
5. 删除 `BrewDataMode`/`BREW_DATA_MODE`（SNAPSHOT 模式，用户已确认一并删除）。
6. 生成器 `generate.py` 停产 4 个 JSON；`check_algo.py` 不受影响（自带 `--fetch`）；`check_types.py` 随 mock 消亡而删除。
7. 同步活跃文档（handover / api-design / discover-algo / content-plan / README）。

## Scope / Non-goals

**In scope**：上述全部 + `BrewResponseData`（mock 信封接口，无使用点）、`BREW_CATALOG_MEMBERSHIP`（"关掉退回快照"的语义随快照消亡）。

**Non-goals**：
- 不动 `features/mine` 的 UI 结构（账号/调研/公告/设置区块、MinePackagesView 二级页路由全保留）。
- 不动 `ResponseData.ets` 文件（`PageData` 仍被列表模型使用，只是 `ResponseData` 接口变孤儿，留着无害）。
- 不更新 `docs/superpowers/` 下的**历史** spec/plan（它们是带日期的记录，引用快照属正常）；只改"活着"的文档。
- 不动 `BrewSourceStore` 的"会话快照"（那是源注册表冻结，与本任务的 brew 数据快照无关）。
- 不删 `.brewgen/` 本地缓存目录。

## Current State And Constraints

- `mockdata/` 目录**只剩**这 4 个 brew 文件，其余 mock 已在前几轮清理中删除。
- 读取链路（唯一）：`BrewService` 4 个方法 → `HmosRequest`(MockRequest) 读 `rawfile/mockdata/<trigger>.json`：
  - `getDiscoverPage()`(:355) ← `BrewDiscoverModel.getDiscoverPage()`（Repository :432，先读快照再用目录成员覆盖）
  - `getInstalledFormulae/getInstalledCasks/getOutdated`(:1457-1467) ← `BrewLocalModel` ← `MinePackagesUtil.loadSets()`（Mine 页唯一数据源）
- Discover 成员/数字/分类/featured 已全部可设备端现算（`BrewCatalogAlgo` + `BrewTaxonomy` + `buildFeatured`），快照只剩「目录拿不到时的回落」（见 brew-discover-algo.md §7.5）。
- `BREW_DATA_MODE` 守卫共 9 处：BrewService :391/:796/:1177/:1303/:1508/:1560，BrewRepository :112/:261/:598。
- Mine 失败处理已就绪：`MinePageVM` catch → 计数清零；`MinePackagesVM` catch → FAILED 态。空集 resolve 后走 SUCCESS 空列表，更平滑。
- `BrewDiscoverBoardVM.load` 按 `board.id` find，找不到给 FAILED 态——骨架 id 保持 1..6 即可稳定路由。
- ArkTS 约束：删除时注意 import 清理（`import type` 与值导入分开）；`Record<string, BrewDiscoverMeta>` 等类型不动。

## Design

### D1. Discover：代码骨架 + 目录成员唯一来源

`BrewDiscoverModel.getDiscoverPage()`（BrewRepository.ets :432）重写：

```
emptyDiscoverPage()  // 新私有静态：6 张榜骨架
  → service.getCatalog()
      ├─ catalog === undefined → 记日志 'discover empty (catalog unavailable)'
      │     BrewNetNotice.settle(...) 后返回空骨架   // ⚠ 必须与 getCatalog 内部的 willFetch 成对，否则提示常驻
      └─ catalog 有值 → applyCatalogMembers(page, catalog)   // 原逻辑不变，去掉 BREW_CATALOG_MEMBERSHIP 条件
            → fillCategoryKeys(page)（不变）
            → hydratePage(page)（简化，见下）
            → BrewLoadLog.info('discover_page','assembled',…) + BrewNetNotice.settle(...)（不变）
```

骨架构造（顺序与旧快照/生成器逐字一致，保证 boardId 1..6 不变）：
- kind 外层 `[BrewKind.FORMULA, BrewKind.CASK]`，内层 `BREW_CATALOG_BOARDS`（trending/alltime/fresh，从 `BrewCatalogAlgo` 新增 import）。
- 每张 `BrewDiscoverBoard`：`id = sequence = 1..6`、`entries = []`、`entryCount = 0`；`page.topN = BREW_CATALOG_TOP_N`、`meta = {}`、`snapshotDate = ''`、`featured = []`。

删除/简化：
- 删 `BrewService.getDiscoverPage()`（:348-356）及远端 section 头。
- 删 `auditCatalogMembers`（:474-493，对账日志，无快照可对）。
- `hydratePage(page, membersFromCatalog)` → `hydratePage(page)`：删模式守卫（:598）、删 `!membersFromCatalog` 的 `sortBoard` 分支；`applyFormulaEntry/applyCaskEntry` 去掉 `metricsFromLive` 参数（恒 false），只留 desc/name/categoryKey 回填；`applyMetrics`、`sortBoard` 整体删除（无调用点）。
- `applyCatalogMembers` 保留，内部 `page.topN > 0 ? … : BREW_CATALOG_TOP_N` 不动（骨架已设好 topN）。

const boards: BrewDiscoverBoard[] = (result.boards ?? [])

## Risks And Compatibility

- **Discover 离线/首装变空态**：失去"断网评审演示"能力（此前仅 Discover 有回落）。与 Formulae/Casks C 档一致，用户已接受。
- **Mine 三区块显示 0/空**：用户已确认空态保壳。若未来接真实本机包管理，恢复点 = git 历史 + `MinePackagesUtil.loadSets` 签名未变。
- **BrewNetNotice 配对**：空目录分支必须 `settle`，否则"正在获取"提示常驻——验证时留意 `[notice]` 日志。
- **boardId 稳定性**：骨架 id 1..6 与旧快照完全一致，二级页路由零影响。
- **boardView 的 snapshotDate 空串**：仅当"目录有值但 windowEnd 为空"才可能出现，旧代码同样存在，不新增处理。
- **check_algo 数据管道**：不受影响（自带 --fetch）；README 用法需同步更新否则照旧命令会因 `.brewgen/discover` 无新数据而用旧缓存（非错误，但文档要写对）。

## Rollback

全部改动在 `dev` 分支上以少量提交落地（建议：①应用侧删除 ②工具与文档）。回滚 = `git revert` 对应提交；若只想恢复数据文件：`git checkout <prev> -- common/src/main/resources/rawfile/mockdata/` 并 revert 应用侧提交（MockRequest/TriggerEnums 与 4 处调用点必须一起回来，否则运行期静默失败）。生成器产物可随时用 `git checkout <prev> -- hmosword-build/` 找回。
